Notes de conception (jalon 0) — Cet écran ne définit aucune donnée propre : chaque carte est un véhicule de SIM.vehicles (_shared/sim-data.js), le même référentiel que Live Tracking, Remorques et Dashboard — 7 missions actives, jamais une seconde liste. La carte commence par la remorque (RQ-xxx), conformément à la consigne d'harmonisation ; les camions restent en TR-xxx en attendant la confirmation de la convention Cxxx (displayId()). Le résumé tient sur la carte ; le détail complet (comparaison d'identité, preuves, résolution) s'ouvre dans un modal au clic — rien n'a été retiré, seulement déplacé.

« Valider » / « Confirmer et résoudre » — ce jalon 0 n'a pas de backend : ces actions posent une marque locale à la session (rechargez la page pour revenir à l'état d'origine), affichée à côté du statut réel du référentiel, jamais à sa place. Rien n'est supprimé ni réécrit : la déclaration d'origine (guérite, iButton, GPS) reste visible telle quelle dans le détail de chaque mission.

Cette file n'invente aucun statut — « Rejetée » n'existe pas dans le cycle de vie de la mission (cahier des charges Missions §2.2 : Planifiée → Détectée → Rapprochée → Proposée → Validée → Clôturée, + Anomalie à tout stade) ; ce filtre n'est donc pas proposé ici.
